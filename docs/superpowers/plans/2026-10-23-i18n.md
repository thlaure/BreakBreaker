# French / English translation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let players switch the whole game (landing page and `/play/`) between French (default) and American English, with a two-pixel-flag selector.

**Architecture:** A pure `t(key, params)` over typed per-domain catalogs (`src/content/i18n/fr/*.ts`, `en/*.ts`, same keys, merged in `src/content/i18n/index.ts`). The simulation emits no phrases: only stable ids that the HUD/render translate. The landing page is generated as two static pages (`/`, `/en/`) at build time from the catalogs; the game reads the saved locale.

**Tech Stack:** TypeScript strict, Phaser 4, Vite plugin (`vite.config.ts`), Vitest.

**Spec:** `docs/superpowers/specs/2026-10-23-i18n-design.md`

## Global Constraints

- Default `fr`; second `en` (American English). Never guess from the browser.
- Locale stored in `localStorage` (guarded with try/catch), `?lang=en|fr` overrides and is saved; `<html lang>` follows.
- `src/sim` stays free of any phrase and any dependency on the locale (determinism); events/snapshots carry ids, not text.
- Jokes are adapted for the English version (transcreation), same tone and comparable length; no real names of people or parties; content rules in `AGENTS.md` apply to both languages.
- Files under 400 code lines; catalogs split by domain so tasks can run in parallel without conflicts.
- Browser checks: none per task (see `AGENTS.md`); the final global check is done separately.
- Gates per task: `npx tsc --noEmit`, `npm run lint` (0 issues), `npm run format:check`, `npx vitest run`, `npm run bench` ≤ 0.3 ms/step. Commit trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Never push.

## Review Focus

- A key present in `fr` and missing in `en` (or an empty English string) must fail a test.
- A string with a plural or a number (« 15 casseurs » / « 15 rioters », « 1 caisse ») renders correctly for 0, 1 and many.
- Locale storage unavailable (private window): the game still starts in French.
- A sim event or snapshot containing a French sentence must fail a test (scan the sim sources for accented literals outside comments).
- Switching language in the pause menu mid-game does not reset the game state.

### Task 1: i18n core and language-free simulation

**Files:** Create `src/content/i18n/index.ts`, `src/content/i18n/locale.ts`, `src/content/i18n/fr/core.ts`, `src/content/i18n/en/core.ts`; modify `src/sim/**` where it produces user-facing text; tests `tests/content/i18n.test.ts`, `tests/sim/noPhrases.test.ts`.

**Interfaces:**
- Produces: `type Locale = 'fr' | 'en'`; `getLocale(): Locale`; `setLocale(l: Locale): void` (saves, sets `document.documentElement.lang` when a document exists, notifies listeners); `onLocaleChange(cb: (l: Locale) => void): () => void`; `t(key: Key, params?: Record<string, string | number>): string` with `{name}` interpolation and `plural` support (`t('x', { n })` picks `x.one` / `x.other` when both exist); `Key` is the union of catalog keys; `catalog(l: Locale)`. Catalog domains are registered in `index.ts` by spreading `fr/*.ts` / `en/*.ts` objects (later tasks add files `hud`, `world`, `content`, `landing`).

- [ ] **Step 1 (tests first):** `tests/content/i18n.test.ts`: `t` interpolates `{n}`; plural one/other; unknown locale value in storage falls back to `fr`; `?lang=en` wins and is saved; storage that throws still returns `fr`; `fr` and `en` have identical key sets (iterate all registered domains); no empty English string; English equals French only for an allow-list (`Paul`, `BreakBreaker`). `tests/sim/noPhrases.test.ts`: scans `src/sim/**/*.ts` for string literals containing accented letters or spaces-with-capital phrases outside comments, with an allow-list of data ids; initially lists the existing offenders.
- [ ] **Step 2:** run them, see them fail.
- [ ] **Step 3:** implement the core; find every user-facing phrase produced under `src/sim` (messages such as « Caisse à outils requise », « Abords non sécurisés », service hints/refusals, names/labels in `types.ts`, `config.ts` banner texts, `snapshot.ts`) and replace by stable ids (e.g. `toolboxMessage: 'toolboxRequired' | 'areaUnsafe' | null`, hint ids); update the HUD/render consumers to translate via `t()` with the French text moved verbatim into `fr/core.ts` and English written in `en/core.ts`.
